# ASPECT (Algorithm System for Packing Efficiency Comparison and Testing)

This project is the interactive software instrument developed to empirically validate the research titled: **"OPTIMIZING DYNAMIC 3D LOADING AND UNLOADING FOR DELIVERY VEHICLES USING HYBRID PARTICLE SWARM AND ANT COLONY ALGORITHM"**.

The application provides a high-fidelity simulation environment for the rigorous, head-to-head comparison of three metaheuristic algorithms: standalone Particle Swarm Optimization (PSO), standalone Ant Colony Optimization (ACO), and the proposed novel hybrid PSO-ACO. These algorithms are tasked with solving complex 3D vehicle loading problems using a real-world dataset from Amazon, creating a robust and scientifically sound platform for experimental analysis.

---

## 1. Answering the Research Problem (Chapter 1)

The fundamental purpose of this software is to provide definitive, data-driven answers to the study's **Statement of the Problem**. The core challenge identified in logistics is that conventional packing algorithms are one-dimensional: they are exceptionally good at maximizing how much can be fit into a space, but they critically fail to consider the operational reality of *unloading* packages in a specific, predetermined delivery sequence. This oversight leads to significant real-world consequences: operational bottlenecks, excessive and time-consuming package reshuffling (relocations), and even physically impossible unloading scenarios where packages are trapped.

This software instrument is meticulously engineered to bridge this research gap by providing the direct means to test our research hypotheses and answer our key questions:

*   **How can we quantify unloading efficiency?** The tool moves beyond simple density metrics. For every solution generated by an algorithm, it performs a complete, step-by-step unloading simulation. This allows it to compute the study's novel dependent variables: **Relocation Count**, **Unloading Feasibility**, and **Unloading Sequence Length**. This directly confronts the primary deficiency in existing packing models and provides the necessary data to answer **Research Question 1 (Loading)** and **Research Question 2 (Unloading)** by comparing how effectively each algorithm minimizes wasted operational effort.

*   **How do the algorithms scale with increasing complexity?** The software is instrumented to meticulously track **Computation Time** and peak **Memory Usage** for every single simulation run. This provides the empirical data required to address **Research Question 3**, which investigates how each algorithm's performance and resource consumption scales as the problem size (vehicle volume capacity) increases.

*   **How do the algorithms adapt to real-world disruptions?** A key experimental control implemented in the tool is the **Dynamic Constraint**. When a user enables this feature, the system mimics real-world uncertainty by randomly removing 10-20% of packages from the problem *after* optimization of the chosen algorithm. This forces the algorithm to adapt to a sudden change, testing its robustness and responsiveness—a common challenge in the dynamic world of logistics.

*   **How can we intuitively understand the results?** To make the complex, three-dimensional output of the algorithms tangible and understandable, the tool features an **interactive 3D visualization** of the final packed vehicle. This allows researchers and panelists to explore the solution, rotate the container, and click on individual packages. It transforms abstract metrics into a clear visual model, making it immediately apparent *why* a particular packing arrangement resulted in a high or low relocation count.

## 2. System Architecture and Performance Strategy (Chapter 3)

The software's architecture is a direct, code-level translation of the system designs and flowcharts specified in Chapter 3 of the methodology. It also incorporates a deliberate performance strategy to ensure the research tool is practical for real-time analysis and demonstration on standard hardware.

### Algorithm Implementation
*   **Particle Swarm Optimization (PSO) - (Figure 5):** Implemented in `backend/algorithms/pso_algorithm.py`. This module simulates a "swarm" of candidate solutions ("particles") navigating a search space, where each particle adjusts its trajectory based on its own best-found solution (`pBest`) and the global best-found solution of the entire swarm (`gBest`).

*   **Ant Colony Optimization (ACO) - (Figure 6):** Implemented in `backend/algorithms/aco_algorithm.py`. This module models the foraging behavior of ants. It uses a constructive approach where "ants" build solutions piece by piece based on "pheromone trails," a shared, collective memory that reinforces which solution components have historically led to high-quality results.

*   **Hybrid PSO-ACO Algorithm - (Figure 7):** The core of this research, implemented in `backend/algorithms/hybrid_pso_aco_algorithm.py`. This novel architecture integrates ACO's pheromone mechanism directly into PSO's particle update step. This creates a powerful feedback loop where the broad, global search capability of PSO is intelligently guided by the localized, memory-enhanced refinement of ACO. The hybrid is specifically designed to rapidly converge on solutions that excel in both spatial efficiency (high volume utilization) and operational efficiency (low relocations).

### Performance Optimization Strategy

Running complex metaheuristic algorithms in a web browser presents significant computational challenges. To ensure a fluid and practical user experience, particularly on hardware with limited physical memory, a multi-faceted performance strategy was implemented:

1.  **Strategic Problem Sizing (`INT_MAX_SAMPLE_SIZE = 400`):** Instead of attempting to process the entire raw dataset of over 80,000 items at once—a computationally infeasible task—the system employs volume-constrained stratified random sampling (`simulation_orchestrator.py`). This creates a smaller, yet statistically representative, problem instance that preserves the characteristics of the original data while being solvable in a reasonable timeframe.

2.  **Intelligent Data Caching (`data_manager.py`):** The initial processing of the large Amazon dataset is a slow, one-time operation for any given vehicle size. The results are automatically saved in a local `data_cache` directory. All subsequent requests for the same vehicle capacity will read from this small, clean cache file, making data loading nearly instantaneous.

3.  **Computational Memoization (Fitness Caching):** The most computationally intensive task within a simulation is evaluating the "fitness" of a given packing solution. A fitness cache is implemented within the `simulation_orchestrator`. If an algorithm attempts to re-evaluate a solution it has seen before, the cached result is returned instantly, avoiding redundant calculations and significantly accelerating the optimization process.

4.  **Asynchronous Execution (`main_app.py`):** The entire application is built on an asynchronous, multi-threaded architecture. When a user clicks "Simulate," the heavy computation is offloaded to a background thread on the server. This prevents the user's web browser from freezing or timing out and allows for responsive features like the real-time progress updates in the loader and the "Cancel Simulation" button.

## 3. Pre-requisites

*   Python 3.8+
*   `pip` (Python package installer)

---

## 4. Installation and Setup

1.  **Create a Project Folder:**
    *   Create a new folder for the project on your computer.

2.  **Download and Place Project Files:**
    *   Place all the provided Python files, `requirements.txt`, HTML, CSS, and JS files into the folder according to the specified directory structure (`backend`, `static`, `templates`, etc.).

3.  **Set Up a Virtual Environment (Highly Recommended):**
    *   Open a terminal or command prompt in your project folder and run:
    ```bash
    # Create the virtual environment
    python -m venv venv

    # Activate the environment
    # On Windows:
    .\venv\Scripts\activate
    # On macOS/Linux:
    source venv/bin/activate
    ```

4.  **Install Dependencies:**
    *   With the virtual environment active, install all required libraries from the `requirements.txt` file:
    ```bash
    pip install -r requirements.txt
    ```

5.  **Dataset Configuration:**
    *   This project is configured to use the **2021 Amazon Last Mile Routing Research Challenge Dataset**.
    *   Download the dataset.
    *   Ensure the `eval_route_data.json` and `eval_package_data.json` files are placed inside the following directory path: `backend/almrrc2021/almrrc2021-data-evaluation/model_apply_inputs/`. You will need to create this folder structure inside your `backend` directory.

---

## 5. Running the Application

Once the setup is complete, launch the Flask web server from the project's root directory:

```bash
python backend/main_app.py
```

Open a web browser and navigate to the local address provided in the terminal, which is typically `http://127.0.0.1:5000`.

### How to Use the Tool:

The application interface is divided into a left panel (Initial Dataset) and a right panel (Simulation Results). A "How to Use" guide will appear on the first launch. The following steps outline a typical experimental workflow:

1.  **Open Simulation Settings:**
    *   Begin by clicking the **"Modify Simulation"** gear icon at the top right. This opens the main configuration modal.

2.  **Select an Algorithm:**
    *   Choose one of the three optimization algorithms to test: **PSO**, **ACO**, or the hybrid **PSO-ACO**.

3.  **Choose a Vehicle:**
    *   Select a **Vehicle Volume Capacity** from the dropdown menu. The application will immediately contact the server to load a valid sample set of packages for that vehicle.
    *   The first time you select a new capacity, there will be a one-time delay as the system preprocesses and caches the data. Subsequent selections of the same capacity will be almost instant.
    *   Once loaded, the left panel will populate with the initial vehicle and package data.

4.  **Configure the Dynamic Constraint:**
    *   Use the toggle switch to **enable or disable** the dynamic constraint, as described in Section 1.

5.  **Run the Simulation:**
    *   Press the **"Simulate"** button. A loading indicator will appear, providing real-time feedback from the backend on the algorithm's progress (e.g., "Generation 5 / 10").
    *   You may cancel the process before the simulation begins using the "Cancel Simulation" button.

6.  **Analyze the Results:**
    *   Upon completion, the right panel will display the comprehensive outcome, including final load statistics and a full breakdown of the key performance metrics.

7.  **Visualize the Solution:**
    *   If the simulation produces a valid packing solution, a **"Visualize Packing"** button will appear.
    *   Clicking this will launch a new window containing a fully interactive 3D model of the packed vehicle. You can **rotate (left-click), pan (right-click), and zoom (scroll)** to inspect the layout.
    *   **Click on any package** in the 3D model to highlight it and view its detailed information.
